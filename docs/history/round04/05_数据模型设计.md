# 05 数据模型设计

本文件是第二轮内部设计资料，不属于老师规定的最终提交材料。实施依据为老师原始 DOCX、第一轮四份设计及本轮用户人工确认。Vue 3 + Vite + Element Plus、FastAPI、SQLite 架构保持不变；本轮使用 Python 标准库实现存储层，不引入 HTTP 服务或推荐评分代码。

## 2. 数据表

### restaurants

| 字段 | SQLite 类型 | 约束与语义 |
| --- | --- | --- |
| id | INTEGER | 正整数主键 |
| name | TEXT | 非空、唯一；全部明确命名为模拟场所 |
| type | TEXT | restaurant 或 window |
| location | TEXT | 非空，全部为虚构校园 A-F 区 |
| avg_price | REAL | 参考人均价，元，非负且最多两位小数；不用于菜品预算过滤 |
| business_hours | TEXT/null | JSON 时段数组；null 表示未知 |
| meal_periods | TEXT | JSON 字符串数组，早餐/午餐/晚餐/夜宵 |
| is_open | TEXT | TRUE/FALSE/UNKNOWN；禁止通过字符串真假值判定 |
| status_source | TEXT | simulated_explicit / simulated_schedule / unknown |
| status_at | TEXT/null | 模拟状态所对应的带时区时间；确定状态时必填 |
| distance_m | INTEGER | 相对虚构演示参考点的非负整数米数，不是定位距离 |
| rating | REAL | 0-5，场所模拟评分，不是菜品评分或真实用户评价 |
| description | TEXT/null | 可选说明 |
| updated_at | TEXT | 带时区 ISO 8601 数据版本时间，不代表商家更新 |

### dishes

| 字段 | SQLite 类型 | 约束与语义 |
| --- | --- | --- |
| id | INTEGER | 正整数主键 |
| restaurant_id | INTEGER | 非空外键，引用 restaurants.id；禁止删除仍有关联菜品的场所 |
| name | TEXT | 非空；同一场所菜品名唯一 |
| price | REAL | 菜品参考价，元，非负且最多两位小数 |
| cuisine | TEXT | 非空菜系或类别 |
| taste_tags | TEXT | JSON 数组，固定口味词表 |
| dietary_tags | TEXT | JSON 数组；目前“素食”允许蛋奶，不表示纯素或无过敏风险 |
| ingredients | TEXT/null | 主要食材字符串数组；null 为信息未知 |
| avoid_tags | TEXT/null | 显式忌口标签数组；null 为信息未知 |
| allergens | TEXT/null | 明确过敏原数组；null 为信息未知 |
| possible_allergens | TEXT/null | 可能含有的过敏原数组；null 为信息未知 |
| description | TEXT/null | 可选说明 |
| updated_at | TEXT | 带时区 ISO 8601 版本时间 |

### dataset_info

单行元数据表：`id=1`、`schema_version=1`、`data_version=campusbite-mock-v1`、`is_mock=1`、模拟说明 `notice`、距离参考点 `distance_origin`、版本时间 `updated_at`。第三张表用于数据透明性和版本检查，不改变业务双表关系。

## 3. 约束层次与未知信息

- 三张表使用 SQLite STRICT 类型约束；每次连接开启 `PRAGMA foreign_keys=ON`。
- 数据库约束主键、关联、非空文本、金额、整数距离、评分、状态枚举、JSON 数组外层格式。同名菜品仅在同一场所内限制重复。
- 导入和读取边界进一步校验标签元素类型、重复标签、口味/过敏原词表、营业时间内容、带时区日期及字段完整性。
- JSON 的内部格式与时间语义由 Python 校验，数据库单独不能阻止所有语义错误；外部直接改库后，读取模块会拒绝错误记录，不能绕过读取层。
- 可选字段允许显式 null，但输入必须包含相应键以防导入拼写或遗漏；业务必填字段缺失或非法值抛出 `DataValidationError`。
- `[]` 表示该模拟记录明确列出“无已声明项”；null 表示未知。两者都不提供现实食品安全保证。
- null 对应未知信息，不额外保存与标签容易不一致的全局“安全”布尔字段；同一菜品对不同用户限制可能得出不同三态结果，因此忌口满足状态应在后续按具体限制派生。
- UNKNOWN 场所仍可在未要求营业筛选的列表中展示；`only_open=True` 时明确排除 UNKNOWN 与 FALSE。
- 目前种子使用明确模拟状态，TRUE/FALSE 对应固定演示时刻 `2026-10-09T12:00:00+08:00`，不随机器当前时间变化；UNKNOWN 未提供状态时刻。尚未实现按当前时间计算营业状态，`simulated_schedule` 为预留来源枚举。

### 后续三态判断与严格条件约束

| 状态 | 营业谓词“是否营业” | 忌口谓词“是否满足该限制” | 明确要求下是否保留 |
| --- | --- | --- | --- |
| TRUE | 模拟数据明确表示营业 | 模拟信息足以明确确认满足该限制 | 保留；多项要求须全部为 TRUE |
| FALSE | 模拟数据明确表示不营业 | 模拟数据已知含有禁忌食材或过敏原 | 排除 |
| UNKNOWN | 无法判定营业 | 可能含有、所需信息为 null、信息不足或限制无法可靠识别 | 排除 |

严格判断必须联合检查与具体限制有关的 ingredients、avoid_tags、allergens、possible_allergens 信息。已知命中优先判为 FALSE；无已知命中但存在相关不确定性判为 UNKNOWN；只有信息足以明确确认时才判为 TRUE。不得仅凭列表未命中、[]、素食标签或字段非空就宣布满足全部限制；不支持的忌口词不能默认为满足。

用户明确要求当前营业时只允许营业谓词 TRUE；不应以 Python 字符串真值判断状态，因为 "FALSE" 和 "UNKNOWN" 也都是非空字符串。现有 only_open 筛选已使用精确相等比较。

未提出严格限制时可展示未知信息，但不能把它标记为安全。用户的严格忌口或营业要求不会因为结果太少而被自动放宽。所有结果、状态和解释均限于模拟数据，不代表实时营业或现实过敏安全保证。这些为后续接口、筛选及推荐实现的强制约束，不是本次已运行的忌口分类结果。

统一营业格式为 `[["10:30", "14:00"], ["16:30", "20:00"]]`，使用 HH:MM、同日升序、无重叠；空时段数组无效，未知应使用 null。本轮不支持跨午夜时段，若后续需要必须明确扩展格式与边界测试。

金额采用 SQLite REAL 以保留第一轮 number 类型；导入时用 Decimal 校验最多两位小数，SQL 用小数精度容差检查。工程边界为非负且小于十亿元；课程模拟范围仅 3.5-32 元。此存储仅供查询和演示，不用于支付结算。

## 4. 模拟数据覆盖

6 个场所各 5 道菜：川味、面食、米饭、轻食、早餐、夜宵。价格 3.5-32 元，距离 100-1600 米，场所评分 3.8-4.8；覆盖清淡、香辣、麻辣、微辣、酸甜、鲜香、甜口和含蛋奶的素食样例。

常见过敏原固定词表：花生、大豆、小麦、鸡蛋、牛奶、鱼、虾、芝麻、坚果。食材与忌口标签另外记录香菜、辣椒、牛肉等信息。29 号烤玉米含“可能含花生”信息；30 号模拟配方待补全饭保留合法 null 风险信息，作为透明表达未知的正常记录，不是非法字段测试数据。未知信息不得构造“满足忌口”的推荐理由。

全部地点、名称、距离和评分均为教学设定；未创建用户、评价或定位记录，未连接第三方 API。

## 5. 模块与调用

| 文件 | 职责 |
| --- | --- |
| backend/data/schema.sql | 表结构、约束和索引 |
| backend/data/seed.py | 固定、可复现的模拟数据 |
| backend/data/validation.py | 数据类型、标签、时间、金额及读取边界校验 |
| backend/data/database.py | 连接、事务、幂等初始化、完整性检查 |
| backend/data/repository.py | 菜品/场所/元数据读取，关键词、字段筛选及排序 |
| backend/data/__main__.py | init/check/query 命令行入口 |
| backend/tests/test_data.py | 独立临时库测试 |
| backend/verify_data.py | 实际命令验证及执行证据生成 |

`FoodRepository.dishes()` 返回菜品及嵌套 `restaurant` 对象，不扁平覆盖两表 id、价格、评分或更新时间。`dish(id)` 不存在时返回 None，由后续接口层转换为 404。错误记录抛出数据异常，由后续 FastAPI 层转换为友好响应；本轮不声称完成接口失败的页面处理。

关键词对名称、关联场所名称/位置、菜系、描述和标签做字面匹配，不将用户字符串拼入 SQL；排序只支持固定 id、price、distance、rating。稳定次序以菜品 ID 打破同值并列。支持普通字段排序不等于实现综合推荐排序。

## 6. 初始化与可复现性

在项目根目录执行：

```powershell
python -m backend.data init
python -m backend.data check
python -m backend.data query
python -m unittest discover -s backend/tests -v
python backend/verify_data.py
```

默认库为 `backend/storage/campusbite.sqlite3`，根据模块路径定位，不依赖终端当前目录；CLI 支持 `--db` 指定另一个文件。只读查询禁止悄悄创建空库。

初始化先校验所有输入，再创建表，并在同一数据事务内写入元数据、场所和菜品。已有 ID 与种子完全一致则跳过；不一致或版本不兼容则报错，不覆盖现有记录。外键失败会回滚全部数据写入，建表操作可能保留空表。不会无限添加重复记录，也不清空未知数据。
