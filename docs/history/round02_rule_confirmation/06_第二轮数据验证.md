## 2. 实际执行的命令

以下命令在项目根目录实际执行；完整 Python 可执行文件路径和时间见 execution.jsonl：

```powershell
python --version
python -c "import sqlite3; print('SQLite', sqlite3.sqlite_version); print(sqlite3.connect(':memory:').execute('select json_valid(?)', ('[]',)).fetchone()[0])"

```

首次测试调用后实际输出 `TEST_EXIT_CODE=0`。验证脚本实际依次调用以下五条子命令，均保存各自输出及退出码：

```powershell

python -m backend.data init
python -m backend.data check
python -m backend.data query
python -m unittest discover -s backend/tests -v
```

不是仅列建议命令：前两次初始化均实际返回 restaurants=6、dishes=30；check 再返回相同计数；query 返回真实元数据及预算 15 元内按价格排序的前三个样本：21 号小米粥 3.5 元、22 号豆浆 4 元、24 号芝麻烧饼 5 元。该 query 是字段查询样本，不是 Top 3 推荐。

## 4. 发现的问题与处理

1. 第一轮价格方向冲突：用户人工确认采用预算内低价高分公式，已修订 docs/01-04；评分算法本轮未实现，不能声称其测试通过。
2. 第一轮单表/价格混用：用户确认双表，已修订字段归属并用预算测试防止 avg_price 混用。
3. 严格忌口确认消息截断：明确请求补全；保留 null 未知信息，未猜测剩余规则。尚未解决。
4. 环境原先普通沙箱命令启动失败：真实错误为 `helper_unknown_error: apply deny-read ACLs`；经受审查的执行方式可以正常读取及运行。不是数据库业务失败。
5. 首次 PowerShell 测试输出将 unittest 的 stderr 包装成 `NativeCommandError`，同时实际测试为 OK/exit 0。保留 tests_01.txt，增加验证脚本通过 subprocess 分别捕获 stdout/stderr 和退出码，后续真实执行输出清晰。未删除测试或修改预期来获得通过。

本轮没有实际失败的自动化测试；校验测试中预期抛出异常并成功断言属于测试通过，不冒充“先失败后修复”的迭代证据。

## 5. 未解决的风险与边界

- 严格忌口过滤尚未完成；调用者不能自行把读取记录中的 null 当作安全。收到用户完整规则后，需要补充三态判断、严格过滤及可能含有/未知的测试。
- 词表覆盖教学样例，尚无海鲜/鱼虾等同义词或类别展开；未经确认不能保证任意自然语言忌口准确匹配。
- 当前固定模拟状态不会随真实时间更新；simulated_schedule 来源仅预留，动态营业计算未实现。
- JSON 内部元素和时间语义依赖 Python 读取/导入校验；直接写库可能产生 JSON 外层合法但语义无效的数据，此类数据会被读取层拒绝。
- REAL 金额仅用于课程展示与预算边界查询，不适用于真实支付；本轮未连接支付或外部服务。
- 数据版本冲突拒绝初始化，不自动迁移；已有不同版本需要人工审查迁移方案。
- 本轮仅存储与查询，尚无 FastAPI 接口、Vue 页面、综合推荐排序、推荐理由或截图证据，不声称满足整个课程最终验收。
