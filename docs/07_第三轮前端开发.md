## 3. 数据来源与接口约定

唯一业务数据源仍为 `backend/storage/campusbite.sqlite3`。前端没有另一套餐厅、菜品、价格或配方模拟数据；测试中的请求拦截样例仅用于独立异常验证。

| 接口 | 返回内容 |
| --- | --- |
| GET /api/restaurants | items、total、metadata；实际 6 个场所 |
| GET /api/dishes | items、total、metadata、options；菜品中包含关联 restaurant 对象 |
| GET /api/dishes/{id} | item、metadata；不存在时 404，编号格式非法时 422 |

列表参数：`keyword`、`budget`、`max_distance_m`、`min_rating`、`taste`、`cuisine`、`meal_period`、`only_open`、`sort`，以及可重复出现的 `avoid`。例：`?budget=15&taste=清淡&max_distance_m=500&only_open=true` 实际返回 4、7、9 号菜。

排序固定为 id、price、distance、rating；相同值由菜品 ID 稳定打破并列。预算仅使用 dishes.price，不使用 restaurants.avg_price。非法参数返回 422 和中文错误结构；存储不可用或损坏返回 503 及友好信息，不向浏览器泄露数据库路径或堆栈。Vite 将 /api 代理到本地 FastAPI，前端请求保持同源，无额外 CORS 配置或第三方业务 API。

## 4. 严格忌口与未知状态

`backend/data/restrictions.py` 按“是否满足该条限制”计算三态，本轮仅用于列表硬筛选：

- TRUE：限制属于受支持的模拟词表，四个风险字段均为已声明数组、食材不为空，没有明确命中或相关可能风险。
- FALSE：明确食材、忌口标签或明确过敏原命中限制；即使其他风险字段未知，明确冲突仍优先判为 FALSE。
- UNKNOWN：限制无法可靠识别、任一必要字段为 null/缺失、食材为空或 possible_allergens 命中该限制。

有严格限制时，每个限制都必须为 TRUE 才保留；FALSE 与 UNKNOWN 都排除，不能因结果少而放回。判断依赖本数据版本的受控模拟声明，不凭单个标签未命中或素食标签就宣布安全；并不代表实际食品配方完整性或现实过敏安全保证。当前 supported 词表为 9 类过敏原以及香菜、辣椒、牛肉、猪肉、鸡肉。未识别词返回 UNKNOWN，未做自然语言或“海鲜”等类别推断。

实际验证：选择花生时，1、8 号明确含花生、29 号可能含花生、30 号配方未知均被排除；其余 26 条仅作为模拟声明符合此限制的列表结果。四个风险字段单独未知的情况均覆盖自动化测试。多个 avoid 之间采用 AND。

`only_open=true` 仅保留 is_open 精确为 TRUE 的结果；FALSE、UNKNOWN 不通过。营业状态依然是固定模拟时刻的声明，尚未实现当前机器时间的动态计算。界面文字为“仅看模拟营业中”，不冒称实时状态。

## 6. 安装、启动与实际命令

项目内便携 Node 实际版本 v24.21.0；从 nodejs.org 下载并校验官方 SHA-256。Python venv 位于 .venv，实际安装 FastAPI 0.143.0、Uvicorn 0.54.0、httpx 0.28.1 等 17 个锁定依赖；前端确切版本见 package-lock.json，实际 Vite 为 7.3.7。运行库和依赖位于本项目，不修改全局 Node/Python 环境，不接入付费服务。

以下安装步骤已真实执行，完整路径和命令数组见 execution.jsonl：

```powershell
python scripts/setup_node.py
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

前端 install/build/test 命令实际由 portable node 调用其 npm-cli.js，以免系统 PATH 缺少 Node。当前项目可按以下命令启动，所有命令从根目录开始：

```powershell
# 便捷启动：必要时选择其他空闲端口，实际 URL 会输出并记录
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_dev.ps1

# 或在两个独立终端手动启动
.venv/Scripts/python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000

$env:PATH = (Resolve-Path '.tools/node-v24.21.0-win-x64').Path + ';' + $env:PATH
Set-Location frontend
npm.cmd run dev -- --port 5173
```

手动启动前端默认代理 http://127.0.0.1:8000；如果手动使用其他后端端口，启动前设置 `$env:CAMPUSBITE_API`。便捷脚本自动设置匹配的代理地址。手动启动时若端口被占用，使用便捷脚本或换到空闲端口，不能覆盖其他进程。

本轮实际保留的可访问服务为：前端 http://127.0.0.1:5173，后端 http://127.0.0.1:8000。服务进程与启动时刻记录在 `.tools/dev-server.json` 及本轮 servers_*.json；后台窗口隐藏。重新启动脚本不会覆盖既有服务器，会另选端口；测试配置自动读取最近一次启动的前端地址。

## 8. 真实问题及修复

1. 系统缺少 Node/FastAPI：先核对现有运行时，再建立 .tools 便携 Node 与 .venv，安装本轮实际所需依赖。没有更换技术栈或写静态页面代替运行。
2. 命令记录器 GBK 编码错误：构建与单元测试子进程实际成功，但记录器打印工具符号时出现 `UnicodeEncodeError: 'gbk' codec can't encode character`。JSONL 已写入子进程输出，终端失败保留在真实会话中；修订记录器 stdout/stderr 为 UTF-8 后重新运行最终验证。
3. 后台启动的捕获管道未结束：服务已可访问，记录器仍等待被后台子进程继承的 PIPE 关闭。只停止本轮已识别的卡住记录器及自建服务，保留日志；改用临时文件捕获 stdout/stderr 后重启，实际启动命令退出码 0。
4. 首次浏览器测试 12 通过、3 超时：测试误点击 Element Plus 的隐藏 combobox 输入。将交互改为点击可见选择框、可见勾选标签；原失败场景全部保留，第二次 15 项全通过。原报告、trace 和上下文在 first_browser_run/，第二次报告在 second_browser_run/。
5. 真正的单项清除 bug：补查清除口味后预期 30 张卡片，实际 0 张且 API 返回 422；清空值被序列化为字符串 undefined。先保存 clear_filter_failure/ 中真实报告、截图和 trace，再修改 Explore.vue 的 URL 参数构造，排除 null/undefined；保留回归用例，最终全部 17 项通过。没有通过删除断言或忽略 422 获得通过。

未解决但不影响已验证功能的提示：构建产物主 JS 约 1.06MB，Vite 提示可拆分；npm 对现有 lucide-vue-next 包名给出弃用提示；Starlette 测试适配器对 httpx 给出弃用提示；测试进程有 NO_COLOR/FORCE_COLOR 提示。均保留在真实输出，未声称零警告。后续可在独立维护改动中进行按需组件加载与依赖迁移，不为消除提示擅自改动业务规则。
